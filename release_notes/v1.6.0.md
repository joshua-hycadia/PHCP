PHCP 1.6.0 - Perl Hydraulic Calculation Program

A Hardy Cross loop-balancing hydraulic solver for fire sprinkler and hydrant systems: a plain-text command language for the model (`.phc`), three windows on that one engine, a calculation report in ASCII text or PDF, an AutoCAD exporter and a pyRevit extension. Australian units by default (L/min, kPa, m, mm).

## Downloads

| file | what it is |
|---|---|
| `phcp_editor.exe` | the text editor: write the model, VALIDATE (F4), CALCULATE (F5), WRITE REPORT (Ctrl+R) |
| `phcp_sheet.exe` | the spreadsheet: the same `.phc` file and the same engine, entered as a sheet |
| `phcp_isometric.exe` | the same calculation, drawn on an isometric grid |
| `phcp.exe` | the command line: `phcp.exe model.phc report.pdf`, `phcp.exe --save model.phc` to keep the results in the model, `phcp.exe --json model.phc` for another program, or `--strict` to exit 0 for ACCEPTED only |
| `PHCP_User_Guide.pdf` / `.docx` | new: the user guide, with pictures of the three windows |
| `PHCP_Reference_Manual.pdf` / `.docx` | the `.phc` command reference |

The four programs are self-contained Windows programs with the pipe and fitting database and the report typeface packed inside. They replace the 1.5.0 files in place.

## What changed since 1.5.0

### Check valves at water supplies

- **New commands `NRV <SUPPLY> <CV> [CRACK]`, `NRVMODEL <SUPPLY> <TEXT>` and `NRVLOSS <SUPPLY> <FLOW> <LOSS> ...`**: a non-return valve at a water supply, its make and model, and optionally its loss as the manufacturer's flow and loss curve instead of a Cv. None is assumed.
- A supply whose valve would take water in shuts and leaves the network; a shut valve reopens when its supply's pressure would lift it. Each change re-solves the network, in every demand search, conditional minimum, joint demand and scenario.
- A part of the network that no open supply can reach is **LOSS OF SUPPLY**: shown with no flow, the outlets cut off named, and the result NONCOMPLIANT (SUPPLY_ISOLATED). A valve still changing after 8 re-solves is INDETERMINATE.
- A valve run beyond its NRVLOSS curve is refused. Report Section 10 and the JSON's `supply_check_valves` give each valve's state, flow, pressure, loss and the basis of the loss; the results block saved into the `.phc` keeps the valve states.

### Acceptance hardening (the audit of 11 November 2026)

Each item was a calculation PHCP accepted, or a check it did not make, on 1.5.0; each is now a test that failed before its correction.

- **Constants and settings**: HW_CONST within 2 % of 6.05E7, C from 40 to 200, the viscosity of water, and every tolerance above zero. HW_CONST 0, 6.05E5 and 4.52 were accepted.
- **Verification apart from the solver's tolerance**: loop closure and the element equations are checked to a fixed 0.1 kPa, whatever TOL_LOOP is set to. A loose TOL_LOOP was accepted 21 kPa out of balance.
- **Supply demands**: every demand-search trial is classified, and a search ending on an invalid or unconverged trial is UNRESOLVED, not a weak supply. The joint demand's supply flows are checked against the net demand.
- **Devices**: an orifice plate off its duty by more than 10 %, a curve run beyond 1.5 times its highest flow, and a dry pipe valve with no usable loss data are refused.
- **The results**: the JSON's `approved` and `demand_assessment`; `--strict` (exit 0 for ACCEPTED only, 4 for NONCOMPLIANT); the results block's CHECK, so an edited block reads as TAMPERED; NOT FOR DESIGN USE unless ACCEPTED. The Revit extension shows NOT AN APPROVED DESIGN unless ACCEPTED.
- **Two corrections for a gravity tank at 0 kPa**: it was REJECTED as unreachable, and its demand point came out a hair above zero.

### Validation

- **Independent benchmarks** (`tools/test_benchmarks.pl`): the element equations against their published forms, and networks against a nodal Newton solve written in the test.
- **Impossible models** (`tools/impossible/`): models that must not be accepted, run through the built `phcp.exe` in CI.
- **The comparison with other calculation programs re-run** on all 900 models (`comparison/RERUN_2026-11-11.md`): the largest change in a required supply pressure since 1.0.0 is 0.004 %. The re-run found that models with a backflow preventer and a pressure reducing valve had become 26 times slower; that is corrected (T047: 6.2 s to 0.4 s, the same requirement).

### Documents

- **A user guide** with pictures taken from the programs, and the user guide and reference manual as Word and PDF, attached to this release.

No solved flow or pressure of a valid model without an `NRV` line changed, apart from the gravity tank at 0 kPa. JSON interface 2 is unchanged; its new fields are additions. A model that 1.5.0 accepted may now be refused: that is the purpose of the audit.
